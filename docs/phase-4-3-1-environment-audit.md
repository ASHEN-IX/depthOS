# Phase 4.3.1 environment audit

This audit follows the Phase 4.3 Wayland paths from Python launch to KWin, the Qt launcher, the receiver, and cleanup. It also covers the synthetic burst runner and the Phase 3.10.1 native authority regression. No production executable or host deployment script was changed.

| Boundary | Phase 4.3 evidence | Phase 4.3.1 qualification path |
| --- | --- | --- |
| Configuration | Native entry point checked HOME and runtime only. A direct internal invocation could supply other XDG paths | Fixed per-run HOME, config, config search, data, cache, state, and temp roots. Checks require real, owned, mode-0700 directories. A private KWin desktop list must match UUIDs seeded in the private config |
| Session bus | Ordinary entry points created a fresh bus. Internal worker validation relied on address inheritance or an environment marker. The initial service-name list did not prove the daemon belonged to the test | Supervisor creates an explicit pathname bus with no service activation directories. Worker validates the expected path, socket inode, bus ID, and daemon PID/start tick |
| Wayland | The old check accepted a path that existed. Several calls resolved the well-known KWin name at the time of use | Fixed relative display and Wayland-only Qt platform. Verify socket type, owner, inode, unique D-Bus owner, and compositor PID/start tick. Script calls address the pinned unique name |
| Qt and library paths | Normal outer launches rebuilt most of the child environment. Internal entry points had no complete allowlist | Fixed system executable path and system XDG data directory. No inherited QT_PLUGIN_PATH, QML_IMPORT_PATH, QML2_IMPORT_PATH, DISPLAY, WAYLAND_SOCKET, or KWIN overrides |
| Observer | Phase 4.3 loaded the repository script directly. This did not exercise package installation at all | Explicit per-run package root checked before calling KPackage. Installed source is loaded and unloaded through the pinned private KWin owner. Uninstall and reinstall are verified |
| Processes | Direct child handles and an outer process-group signal covered ordinary exits. A process creating its own group could escape this cleanup | Subreaper and descendant enumeration with pidfds. Interruptions and setup failures are tested. A deliberately detached fixture is reaped |
| Filesystem and IPC | Directory settings were convention. A descendant could still open host paths or sockets by absolute pathname | Landlock denies outside-root filesystem writes and new outside-domain pathname and abstract UNIX connections. Signals are confined to the domain. Every run proves outside-root write and both UNIX socket denials on disposable endpoints |

The private Wayland environment enables only the local KWin default-keymap override and software OpenGL preference. No KWin permission-bypass flag is set. The system D-Bus address is explicitly pinned to a nonexistent private path. A device exception permits only writable opens of `/dev/null` and discovered DRM render nodes, verified as character devices. The raster Qt fixture needs no host pseudo-terminal. The Phase 3 legacy runner keeps its own nested daemon, now inside this same outer sandbox.

The commands in the Phase 4.2 observer host deployment plan are excluded from tests. They remain explicit host operations and require separate approval. The sandbox does not claim to hide host files from reads, mediate every metadata syscall, or contain arbitrary untrusted executables. Remaining permissions and monitoring limits are documented in the security review.
